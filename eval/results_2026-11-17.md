# Evaluation Results: November 17, 2026

Results for the 24 questions in `eval/questions.md`, run against the BLM Mining Claims MCP server on the local computer, using the live public BLM and USGS services. Source for section 3 of the evaluation report (submitted separately).

## How the runs were done

**Agent run (one pass).**
- Agent: Claude Opus 5.5 (`claude-opus-5-5`) in Claude Code on the personal computer (Windows 11), connected to the server over stdio (`claude mcp add --scope local mining-claims -- uv run --directory <repo folder> mining-claims-mcp`). The agent chose every tool and argument itself.
- When: November 17, 2026, 22:04:42 to 22:09:00 Mountain time. Questions asked one at a time, in order, as independent questions.
- Timing: a timestamp was logged (`date`) at the start of each question; the time for a question is the gap to the next timestamp. It is wall-clock time for the whole answer, including the model's thinking and the logging call. The windows for questions 5, 13, 18 and 23 also include a short progress message to the user.
- Grading: each answer was compared with the expected answer in `eval/questions.md` (fixed facts) or its written behavior criteria (questions marked *Judge*), and with the scope rules (no invented claimant names or links, no amounts outside the fee table, no "the ground is available", MLRS only for what the data lacks).
- **Bias to note:** the agent had read `eval/questions.md` (with the expected answers) before the run and graded its own answers. The tool calls and tool results are real, but the answers are not a blind test. A person should review the grading, and a blind run is still to do.

**Tool checks (three passes).**
- Script: `uv run python eval/run_tool_checks.py --runs 3` (in this folder). It calls the tools through FastMCP's in-memory client, with the arguments an agent needs for each question, and checks the key facts in each tool result in code. Raw output: `eval/tool_checks_2026-11-17.json`.
- When: November 17, 2026, started 22:11:18 Mountain time; one call at a time.
- It checks the tools, not model wording. For *Judge* questions it checks the tool facts the answer depends on (for example, 3 King Mountains by county with the "ask which one" note; no Drumlummon claim and a hint that asks for a township and range or landmark, without MLRS).

**Unit tests and lint (same day):** `uv run pytest tests/ -q`: 595 passed in 9.24 s. `uv run ruff check .`: all checks passed.
